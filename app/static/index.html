Settings & Security

Appearance, session boundaries, runtime configuration and the limits of this build.

Appearance

Theme is stored in this browser only. The system option follows the operating system preference live.

Session & security

The console uses one launch token. There are no separate user accounts or roles.

Checking session… Cookie: HttpOnly, SameSite=Strict, 7-day Max-Age. Mutating requests also require the per-process CSRF token.

Logging out clears this browser's cookie. The launch token is not rotated, and other browsers holding the same token are not revoked.

Local model

Select a model already installed in Ollama. Nothing is downloaded, and the launch configuration is not rewritten.

Web research

Search runs on this server, never in the browser. Results are external observations and stay candidates until reviewed. The privacy profile keeps this off.

Runtime

Read-only values reported by /api/status. Model changes are process-local; other changes require editing the configuration and restarting.

Known limits

These are absent capabilities, not hidden settings.

  • No encryption at rest. Both databases are plaintext SQLite. ASHURA does not encrypt them; filesystem permissions and OS disk encryption are outside this application.
  • No download, quantization or training from this screen. The model list comes from the local Ollama endpoint; only models already installed there can be selected.
  • Model switching is process-local. The launch configuration is unchanged, so a restart returns to the configured model. A response already streaming finishes on the model that started it.
  • No server-side session revocation. Logging out one browser does not invalidate the launch token.
  • No multi-user accounts or roles. The launch token is shared by every client that has it.
  • No TLS. The server binds loopback only and speaks plain HTTP.
  • Web-sourced answers are not verified. Search and page fetching are best-effort, bounded and SSRF-guarded, but the resulting text is untrusted evidence and the fact store exports only review candidates.
  • Local tools are read-only plus a sandboxed note. Agent tools can list, read and search the workspace and write a single note file; they cannot execute shell commands or run arbitrary code.
  • No CPU, RAM, disk, GPU or model-readiness metrics in this build. System Monitor shows those values as not available.
  • No durable failed or cancelled operation history. Only completed assistant turns are persisted.
