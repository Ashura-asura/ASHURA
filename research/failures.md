# Failures and limitations found so far

**F-001 - AMA discard branch nearly unreachable at default weights.** Items >= 0.9 similar are merged before scoring; items below that have novelty >= ~0.1, and an unverified item then scores >= ~0.5, above the 0.45 threshold. Found when my "chatter is discarded" test failed. I did not retune the threshold to pass the test. Action: calibrate on realistic data (EXP-001 sweep is a start).

**F-002 - False conflicts on rewordings. FIXED (with limits), see below.** Same question + differently-worded but equivalent answer (Jaccard < 0.9) is treated as a contradiction: stored as evidence, not indexed, flagged for review. 63% of rewordings in EXP-001. Needs a semantic/number-aware comparison (e.g. compare extracted values) rather than token overlap.
  *Fix:* `learning/ama.py::answers_agree` - answer values (digit-bearing tokens not already in the question) must be identical, negation parity must match, and value-free answers must share >= 75% of their content words. EXP-001 rewording false-conflict rate 63.1% -> 0.0%; 8 adversarial contradictions (transposed digits, negation, hedged extra value, value-vs-none, different city/weekday) are all still caught (tests/test_ama.py). *Remaining limits:* number words vs digits ("four" vs 4), units ("5 km" vs "5 miles"), and paraphrases with no shared content words are NOT understood - they fall back to "disagree" (stored as evidence, never silently merged). The reworded test cases were again written by the same author.

**F-003 - Router RAM guard rejected the already-loaded model (fixed).** With ~4 GB free, the 2.5 GB language model failed the headroom check and nothing could answer. Fix: `resident` modules cost no additional RAM. Found by smoke test, then covered by `test_low_ram_...`.

**F-004 - AMA overhead.** Default AMA is ~5x slower per admission and the DB is larger than store-everything (EXP-001). Acceptable off the response path, but worth reducing before claiming "resource efficient".

**F-005 - Benchmark judge is substring-based and gameable** (see EXP-000). **FIXED:** `evaluation/judge.py` strips copied prompt text, matches whole tokens, and reports a strict score (first line / first word) beside the lenient one; the echo stub now scores 0% (was 18.75%). `baseline_v2.jsonl` fixes the "buenos d" prefix accept and marks yes/no items first-word. Residual: strict mode can under-credit models that think aloud before answering; the suite is still 16 items by one author.

**F-006 - Arithmetic verification is only independent for + - * /.** For % ** sqrt the verifier reports "no independent check" and the result is NOT marked verified (so it cannot become a DREAM training label).

**F-007 - Adaptive memory has no demonstrated advantage over FTS5.** On lexical lookups FTS5 scored 1.000 everywhere; the neural memory ties only if capacity (dimension) is large relative to the number of facts, and degrades beyond it (EXP-004). Not a bug; a negative-leaning result that must stay visible. Need a semantic-generalisation task and a pretrained/learned encoder to find a case where it earns its place.

**F-008 - Raw hashed-token keys are nearly useless without IDF weighting** (shared template tokens dominate). Any future featuriser must handle common-token dominance.

**F-009 - Same-key conflicting updates** for the adaptive memory: **TESTED (EXP-005).** The neural memory has no reliability gate: the latest write wins at every lr/passes setting tried, so a wrong claim would overwrite a right one. Protection comes entirely from AMA, which never queues a weaker conflicting claim. Long-run interference over many updates is still untested.

**F-010 - Deleted experiences stayed searchable and quotable (FIXED).** `EpisodicMemory.delete` removed only the `experiences` row, leaving its FTS5 entry (still returned by search) AND any derived `facts` row (still quoted as reliable semantic memory). Violated the Phase 1 completion criterion "deleted correctly". Found by reviewing the code, reproduced before fixing. *Fix:* database triggers (`trg_exp_delete_facts`, `trg_exp_delete_fts`) so no path - including raw SQL - can bypass it; `delete()` now runs in one transaction, scrubs the id from other records' `related_ids`, and returns False for unknown ids; `EpisodicMemory.reconcile_index()` repairs databases written before the fix. `admission_log` is intentionally kept as an audit trail. 6 regression tests.

**F-011 - Router checked only RAM (FIXED) and used placeholder costs (PARTLY FIXED).** `NeedField` now defers optional, non-resident, heavy (>= 500 ms) modules when system CPU > 85%; the resident language model is never starved. `default_registry` reads `config/module_costs.json` (written by `ollama_baseline --calibrate`) for the language module; until that is run on the laptop the figures remain placeholders. Costs of non-language modules are still estimates.

**F-012 - AMA surprise was never computed (FIXED, narrowly).** `surprise_from_prior`: 1.0 if memory already held a *different* answer for this exact question, 0.0 if it agreed or held nothing. This is prediction error against memory, not against the language model, and it only fires on exact-question matches.

**F-013 - Forgetting policy missing (FIXED).** `memory/retention.py`: only unverified, never-reinforced, unrelated, non-queued records older than `max_age_days` (or beyond an optional row cap) are forgotten; every removal is logged. The 30-day default and any cap are guesses, not tuned.

**Still open (not fixable without real data or hardware):** F-001 (AMA discard branch / weight calibration needs a realistic stream that includes useful unverified items), F-004 (AMA is ~6x slower per item and its DB is ~24% larger than store-everything), F-006 (only + - * / are independently verified), F-007 (adaptive memory has no demonstrated advantage over FTS5; the semantic-generalisation test needs a real encoder), F-008, and Phase 0 itself (no real-model baseline has been run: `python -m evaluation.ollama_baseline` on the laptop).

**F-014 - The 7B foundation does not fit the target GPU (Phase 0).** `tony_control:7b` scored 0.94 strict but took **50.7 s p50** (90.3 s p95) on the MX350 because the 4.6 GB model exceeds 2 GB VRAM; generation itself was 7.3 tok/s, so most latency was memory movement/CPU fallback. A 7B-on-2 GB plan is not viable. Fix: pin `qwen3.5:2b` (2.3 GB, 4.5 s p50, 16.5 tok/s) as the live foundation; keep 7B only as an offline quality reference.

**F-015 - Qwen3.5-2B is weak at arithmetic (0.20 strict) and only 0.56 overall.** This is expected for 1.9B and is partially masked by routing: arithmetic prompts go to the exact path (smoke test answered 17*23 = 391 in 1.1 ms). It is still a real limitation for any question the router sends to the language model. The 16-item suite is too small to rank models precisely; do not over-read the 0.56.

**F-016 - OCR is implemented but not measured on the target corpus.** The optional local Tesseract adapter, correction store and CER/WER runner pass code-level tests, but no labelled target-document corpus has been run, so accuracy, latency and language coverage are unknown. Do not claim OCR capability from unit tests. Fix: build a held-out JSONL manifest of target scans and run `evaluation.ocr_benchmark` on the laptop.

**F-017 - The "neural" addition candidate is linear least squares, not a neural arithmetic circuit.** It matches exact addition 1.000 on held-out pairs in [-1000, 1000] because it fits a linear function, not because it learned arithmetic. It adds no capability over the exact evaluator. Keep it as a non-authoritative candidate only; a real HARN test needs a nonlinear/digit-level model and a held-out distribution where exact evaluation is not already perfect.

**F-018 - BrainSim B2 saturates and does not test recurrence.** The GRU and a parameter-matched fixed MLP both score 1.000 at every delay, including unseen delays 12-20; the MLP trains 6-16x faster. The task only needs cue copying, so the delay is irrelevant. This falsifies the planned recurrent-advantage hypothesis. Fix: B2b with variable-length cues, distractors that must be filtered, or a relational/delay-dependent query.

**F-019 - BrainSim B3 gating assumes the task ID is already known.** Task-scoped memory retains old-rule accuracy at 1.000 versus 0.104 for shared memory, but the experiment supplies the task ID and uses verified writes, so it bypasses the surprise/admission logic. It is isolation under a known boundary, not learned task identification or general interference control.

## Production-hardening pass (code review; every item below was reproduced before it was fixed)

**F-020 - The CLI crashed on large exact results (FIXED).** `what is 2^20000` raised `ValueError: Exceeds the limit (4300 digits)` from `str(int)` and killed the session. Results above 4000 digits are now printed in scientific notation with the digit count; the process-wide int-string limit is left untouched. A chain of multiplications is also size-checked (it previously bypassed the `**` guard), and deeply nested/NUL-containing input becomes an `ArithmeticError` instead of a traceback.

**F-021 - Dates and phone numbers were "computed" and stored as verified (FIXED).** `2026-11-05` was read as 2026-11-05 = 2010, injected as a known fact and admitted to memory at reliability 1.0. ISO dates, 4-digit-year slash dates and 3-3-4 phone numbers are no longer treated as arithmetic. Spaced forms (`2026 - 11 - 05`) and `100-50-25` still compute. The heuristic parser is still a heuristic.

**F-022 - Routing results depended on the machine's live CPU/RAM (FIXED).** Two OCR tests failed whenever the host was busy; the same load-based deferral could also silently skip OCR when the user had explicitly typed `/ocr`. `NeedField` accepts `ram_fn` (like `cpu_fn`) so tests are deterministic, and `Task.force` lets an explicit request bypass load-based deferral (never availability).

**F-023 - A configured empty `WorkingMemory` was discarded (FIXED).** `wm or WorkingMemory()` is falsy for an empty container (`__len__ == 0`), and `app.main` never passed the config values anyway, so `working_memory_slots/ttl_s` were ignored. Both fixed.

**F-024 - Stale retrieval cache (FIXED).** Facts told in a normal turn were invisible to a question cached before them for up to 10 minutes. Admitting new memory now invalidates cached retrievals for other questions (the current question's own entry is kept so repeats still hit the fast path).

**F-025 - A model-backend failure crashed the request and the error text was learned (FIXED).** `Controller.handle` now degrades (exact answer, else memory, else a clear message) and does not admit the error message into memory. Malformed/`{"error":..}` Ollama responses become `OllamaError`.

**F-026 - Conflict detection scanned the whole experiences table per admission (FIXED).** `find_by_input` loaded every row and normalised in Python. A normalised `input_norm` column with an index is used instead; existing databases are migrated and backfilled automatically. SQLite also gets a busy timeout so a competing writer waits instead of failing immediately.

**F-027 - `pip install -e .` did not work (FIXED).** setuptools refused the flat layout ("Multiple top-level packages"); `pyproject.toml` now lists the packages, ships `schema.sql`, and exposes an `ashura` command. The CLI also finds its config from any working directory.

**F-028 - Smaller robustness fixes.** Unknown `[foundation]` keys give a clear error instead of a `TypeError`; checkpoint names cannot contain path separators; `promote()` copies atomically and refuses to overwrite a *different* stable file; a corrupt manifest gives a readable error; `new_ratio <= 0` no longer reaches a division by zero; the neural addition candidate is cached instead of re-read from disk per request and declines integers above 2**53 (float64 limit; huge ints raised `OverflowError`); adaptive-memory checkpoints are written atomically to the exact path requested (numpy silently appended `.npz`) and refuse to load with a different seed; OCR has a Tesseract timeout; `--calibrate` with a model that isn't being run now fails before the benchmark instead of after it; the benchmark continues past one failing non-reference model; the `[retention]` config section is now honoured by `python -m memory.retention`; the OCR test no longer hard-codes a Windows font path.

**Not changed, needs your decision (F-029).** Retrieved memory is fed to the language model as `Memory:` context regardless of reliability, and the model's own *unverified* answers are admitted into that same memory. A wrong answer can therefore come back later as "memory". AMA keeps unverified items out of semantic facts and the DREAM queue, but not out of FTS5 retrieval. A `min_reliability` filter on retrieval is the obvious fix, but it changes behaviour the experiments were measured under, so it is left for you to decide and re-measure.
